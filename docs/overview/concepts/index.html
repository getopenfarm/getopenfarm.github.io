Key concepts

The normal workflow is: define a part, load a compatible spool, request output, and let a ready printer take the resulting job.

Library and material​

RecordWhat it represents
PartA saved source file or selected plate, its print requirements, and production filament choices.
AssemblyA product definition containing parts and sub-assemblies with quantities. Cost items can be added separately.
Filament and colorA catalog material identity and its color variants, prices, and profile assignments.
SpoolA physical roll, with remaining weight, purchase details, and usage history.
Feed unit and slotThe printer's material path: AMS, external spool, toolheads, or a configured reloader. A tracked spool is loaded into a slot.
ProfileSlicer settings for a machine, process, or filament. Profiles are separate from physical inventory.

Demand, jobs, and runs​

Production demand describes what you want to make. It can exist without a run. A print job is one attempt to print a plate. OpenFarm assigns it automatically, or you pin it to a specific printer. A run groups a fixed production target so you can track an order or batch.

Parts can be requested in whole plates or unit targets; assemblies in a run are requested in complete sets. Exact unit targets can require a partial final plate, which needs reliable object identities. Runs explains this planning flow.

Continuous backfill repeatedly makes whole plates when compatible printers are idle, after jobs with fixed quantities. You can pause it and limit how many printers it uses at the same time.

Readiness has several layers​

A saved part can be incomplete. A complete part can still have no matching printer. A matching printer can be busy or waiting for bed clearance.

Production checks connectivity, availability, confirmed nozzle sizes, file compatibility, tracked loaded spools, profiles, and stock where estimates are known. Use Job diagnosis to see which layer is blocking work.

Recorded work and current configuration​

Jobs with fixed quantities save their production inputs when queued. Running jobs keep those saved inputs. Backfill uses current part inputs until OpenFarm prepares and sends the job. OpenFarm still checks current printer settings before sending.

Editing a library record does not rewrite a completed print's material history. Requeue uses retained production inputs; Outcomes and recovery covers the limits.

File and scheduling terms​

TermMeaning in these guides
ToolpathThe movement and extrusion instructions generated by a slicer. G-code contains toolpaths.
MetadataInformation stored with a file, such as its material, nozzle size, or estimated print time.
Preset or profileA saved set of slicer settings. OpenFarm groups profiles into catalogs by slicer and version.
Slicer pinThe slicer engine and exact version saved for a part. It is separate from pinning a job to a printer.
Pinned printerThe only printer that a job is allowed to use. The job must still pass compatibility checks.
Production snapshotThe source file reference, requirements, and slicer selection saved for a job. Current printer settings and loaded spools are still checked.
Object identityAn identifier in the file that lets OpenFarm distinguish a printable object for quantity checks or object skipping.
DispatchThe process of preparing a job and sending it to a printer.
